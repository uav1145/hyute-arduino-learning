Lập trình truyền thông và giám sát dữ liệu

Thiết kế giao thức trao đổi bản tin qua Serial có ký tự phân định, kiểm tra độ dài và lệnh hợp lệ.

Tư duy thuật toánArduino UNO R3Tinkercad CircuitsTự vẽ mạch
01

Mục tiêu học tập và kiến thức tiên quyết

Hoàn thành bài này, sinh viên có thể: Thiết kế giao thức trao đổi bản tin qua Serial có ký tự phân định, kiểm tra độ dài và lệnh hợp lệ.

Kiến thức tiên quyết: Bài 9–11, 17.

Yêu cầu phương pháp: Trước khi lập trình, sinh viên phải mô tả đầu vào, đầu ra, thuật toán và các ca kiểm thử.
02

Tình huống kỹ thuật khởi động

Người dùng gửi LED=1, LED=0 hoặc STATUS từ Serial Monitor. Hệ thống phản hồi OK/ERR và trạng thái LED.

03

Kiến thức nền tảng

Giao tiếp nối tiếp

Serial.begin(9600) thiết lập tốc độ giao tiếp; Serial.available() cho biết số byte đang chờ, Serial.read() lấy dữ liệu từ bộ đệm.

Khung lệnh

Giao thức cần quy định dấu kết thúc bản tin (newline), chữ hoa/chữ thường, độ dài tối đa và cách phản hồi lệnh không hợp lệ.

Bộ đệm nhận

Không đọc chặn bằng cách chờ vô hạn; lưu byte vào mảng ký tự có ký tự kết thúc chuỗi; kiểm tra tràn trước khi ghi.

Giới hạn kỹ thuật: Đây là ví dụ giao thức đơn giản, không phải giao thức an toàn/đảm bảo truyền. Khi tràn bộ đệm, chương trình bỏ qua phần còn lại cho tới newline để không diễn giải nhầm đuôi bản tin thành lệnh mới.
04

Phương pháp phân tích và xây dựng thuật toán

Thực hiện theo trình tự dưới đây. Mỗi bước phải có thể giải thích hoặc đối chiếu bằng một phép kiểm thử.

  1. Định nghĩa ba lệnh chính xác: LED=1, LED=0, STATUS.
  2. Chọn ký tự xuống dòng LF (\n) để kết thúc bản tin; bộ đệm 16 byte lưu tối đa 15 ký tự nội dung và một ký tự kết thúc chuỗi \0.
  3. Nhận từng byte không chặn và tích lũy vào bộ đệm.
  4. Khi gặp LF (ký tự xuống dòng), chèn ký tự kết thúc chuỗi, xử lý lệnh rồi đặt lại bộ đệm.
  5. Kiểm thử lệnh hợp lệ, sai cú pháp và quá dài.

Hãy tạo thiết kế mới, tự xác định vị trí phần tử và đường nối, sau đó ghi chú mã chân ngay trên bản thiết kế Tinkercad.

06

Dự đoán và kiểm chứng tình huống

Bước 1: Chọn một tình huống, tự dự đoán trên giấy hoặc ghi vào phiếu. Bước 2: Nhấn “Hiện kết quả” để xem giải thích; Bước 3: tái hiện trên Tinkercad nếu phù hợp.

07

Chương trình Arduino tham khảo

Đọc thuật toán trước, sau đó phân tích trách nhiệm của từng hàm hoặc khối lệnh. Hãy tự nhập hoặc sao chép mã vào Tinkercad và kiểm tra bằng các ca thử.

#include <string.h>
const byte LED_PIN = 8;
char buf[16];
byte len = 0;
bool discardUntilNewline = false;
bool ledBat = false;
void xuLy(const char* cmd) {
  if (strcmp(cmd, "LED=1") == 0) ledBat = true;
  else if (strcmp(cmd, "LED=0") == 0) ledBat = false;
  else if (strcmp(cmd, "STATUS") != 0) { Serial.println("ERR: LENH"); return; }
  digitalWrite(LED_PIN, ledBat ? HIGH : LOW);
  Serial.println(ledBat ? "OK: LED=1" : "OK: LED=0");
}
void setup() { pinMode(LED_PIN, OUTPUT); Serial.begin(9600); }
void loop() {
  while (Serial.available() > 0) {
    char c = (char)Serial.read();
    if (c == '\r') continue;
    if (discardUntilNewline) {
      if (c == '\n') { discardUntilNewline = false; len = 0; }
      continue;
    }
    if (c == '\n') { buf[len] = '\0'; xuLy(buf); len = 0; }
    else if (len < sizeof(buf) - 1) buf[len++] = c;
    else { len = 0; discardUntilNewline = true; Serial.println("ERR: QUA DAI"); }
  }
}

Chương trình dùng Arduino C/C++; không có tệp mã đính kèm riêng.

08

Thực hành trên Tinkercad Circuits

Thí nghiệm ảo sử dụng nền tảng của Autodesk.

Mở Tinkercad, tạo thiết kế Circuits mới, kéo linh kiện theo danh mục ở phần 05 và tự nối theo gợi ý. Chuyển phần lập trình sang chế độ Text khi cần.

Mở Tinkercad Circuits ↗

  4. Nộp liên kết thiết kế Tinkercad được chia sẻ đúng quyền truy cập cho giảng viên.
09

Kiểm thử và phân tích lỗi

Mỗi ca kiểm thử cần ba cột: đầu vào, kết quả dự kiến, kết quả quan sát. Nếu khác nhau, ghi nguyên nhân và biện pháp sửa.

TTYêu cầu kiểm thử
1Chọn đúng newline trong Serial Monitor.
2Thử nhập chuỗi chữ thường để nhận ERR.
3Thử bản tin dài hơn 15 ký tự và xác nhận đầu ra không thay đổi; chương trình bỏ qua tới newline.
