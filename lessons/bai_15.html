Thiết kế chương trình điều khiển theo trạng thái

Mô tả chương trình bằng máy trạng thái hữu hạn (FSM), trạng thái và điều kiện chuyển trạng thái có thể kiểm thử.

01

Mục tiêu học tập và kiến thức tiên quyết

Hoàn thành bài này, sinh viên có thể: Mô tả chương trình bằng máy trạng thái hữu hạn (FSM), trạng thái và điều kiện chuyển trạng thái có thể kiểm thử.

Kiến thức tiên quyết: Bài 12–14.

Yêu cầu phương pháp: Trước khi lập trình, sinh viên phải mô tả đầu vào, đầu ra, thuật toán và các ca kiểm thử.
02

Tình huống kỹ thuật khởi động

Mô hình quạt trạng thái: STOP → RUN khi nhiệt độ ≥ 35 °C; RUN → STOP khi ≤ 32 °C; mọi trạng thái → ALARM nếu giá trị ADC đọc được nằm ngoài miền hợp lệ do bài tập quy định; chỉ khi tín hiệu trở lại bình thường và người dùng nhấn RESET mới rời ALARM.

03

Kiến thức nền tảng

Trạng thái hữu hạn

Một hệ thống được mô tả bằng tập trạng thái hữu hạn; chỉ một trạng thái hoạt động tại một thời điểm.

Sự kiện và chuyển trạng thái

Điều kiện chuyển dựa trên tín hiệu, trạng thái đang có và yêu cầu điều khiển. Cần định nghĩa rõ ưu tiên xử lý lỗi trước các điều kiện vận hành.

Lỗi chốt (latched alarm)

Đối với bài thực hành, ALARM được giữ cho đến khi dữ liệu trở lại miền hợp lệ và có thao tác reset; reset không được tự động bỏ qua lỗi đang tồn tại.

Giới hạn kỹ thuật: Miền ADC [80,250] là điều kiện giả định của bài học, không thể được xem là cách phát hiện mọi lỗi cảm biến. Ví dụ dùng giữ nút thay vì phát hiện cạnh và chống dội; nếu ứng dụng thực cần reset theo một lần nhấn hợp lệ.
04

Phương pháp phân tích và xây dựng thuật toán

Thực hiện theo trình tự dưới đây. Mỗi bước phải có thể giải thích hoặc đối chiếu bằng một phép kiểm thử.

  1. Liệt kê STOP, RUN, ALARM và quy ước đầu ra ở từng trạng thái.
  2. Xác định sự kiện tăng/giảm nhiệt độ và phát hiện dữ liệu bất hợp lệ.
  3. Xác định ưu tiên: xử lý lỗi trước, sau đó xử lý điều khiển thường.
  4. Cài đặt enum State và switch(state) trong loop().
  5. Kiểm thử đường đi STOP→RUN→STOP và RUN→ALARM→STOP.
05

Hãy tạo thiết kế mới, tự xác định vị trí phần tử và đường nối, sau đó ghi chú mã chân ngay trên bản thiết kế Tinkercad.

06

Dự đoán và kiểm chứng tình huống

Bước 1: Chọn một tình huống, tự dự đoán trên giấy hoặc ghi vào phiếu. Bước 2: Nhấn “Hiện kết quả” để xem giải thích; Bước 3: tái hiện trên Tinkercad nếu phù hợp.

Đây là bộ giải thích logic, không phải trình mô phỏng vi điều khiển hoặc nguồn điện thực.

07

Chương trình Arduino tham khảo

Đọc thuật toán trước, sau đó phân tích trách nhiệm của từng hàm hoặc khối lệnh. Hãy tự nhập hoặc sao chép mã vào Tinkercad và kiểm tra bằng các ca thử.

enum TrangThai { STOP, RUN, ALARM };
TrangThai state = STOP;
const byte QUAT_GIA = 8, LOI = 9, RESET = 2;
float doNhiet(int adc) { return (adc * 5.0 / 1023.0 - 0.5) * 100.0; }
void setup() {
  pinMode(QUAT_GIA, OUTPUT); pinMode(LOI, OUTPUT);
  pinMode(RESET, INPUT_PULLUP);
}
void loop() {
  int raw = analogRead(A0);
  bool loiTinHieu = (raw < 80 || raw > 250); // miền thực hành giả định
  float t = doNhiet(raw);
  if (loiTinHieu) state = ALARM;
  else {
    switch (state) {
      case STOP: if (t >= 35.0) state = RUN; break;
      case RUN: if (t <= 32.0) state = STOP; break;
      case ALARM:
        if (digitalRead(RESET) == LOW) state = STOP;
        break;
    }
  }
  digitalWrite(QUAT_GIA, state == RUN ? HIGH : LOW);
  digitalWrite(LOI, state == ALARM ? HIGH : LOW);
  delay(50);
}

Chương trình dùng Arduino C/C++; không có tệp mã đính kèm riêng.

08

Thực hành trên Tinkercad Circuits

Thí nghiệm ảo sử dụng nền tảng của Autodesk.

Mở Tinkercad, tạo thiết kế Circuits mới, kéo linh kiện theo danh mục ở phần 05 và tự nối theo gợi ý. Chuyển phần lập trình sang chế độ Text khi cần.

Mở Tinkercad Circuits ↗
  1. Không sử dụng sơ đồ điện do AI tạo. Tự hoàn thành sơ đồ trên Tinkercad.
  2. Kiểm tra chân, cực tính, nguồn và GND trước khi bấm Start Simulation.
  3. Chạy mã đã tự phân tích; ghi kết quả đo hoặc trạng thái với mỗi ca thử.
  4. Nộp liên kết thiết kế Tinkercad được chia sẻ đúng quyền truy cập cho giảng viên.
09

Kiểm thử và phân tích lỗi

Mỗi ca kiểm thử cần ba cột: đầu vào, kết quả dự kiến, kết quả quan sát. Nếu khác nhau, ghi nguyên nhân và biện pháp sửa.

TTYêu cầu kiểm thử
1Kiểm tra đúng ba giá trị trạng thái, không dùng hai cờ bool độc lập mâu thuẫn.
2Kiểm tra lỗi ở STOP và RUN đều đưa về ALARM.
3Kiểm tra reset không xóa ALARM khi dữ liệu ngoài miền.
